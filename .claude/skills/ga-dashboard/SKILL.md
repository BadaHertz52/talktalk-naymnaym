# GA Dashboard (톡톡냠냠 전용)

GA4에 쌓인 이벤트로 "어디서 나가는지, 어느 게임 방식이 덜 해로운지"를 한 장의 HTML로 본다.
비율·평균은 스크립트가 계산한다(Looker Studio 계산 필드로는 담기지 않던 지표).
조회는 읽기 전용이며 GA 설정을 바꾸지 않는다.

## 0단계 — GA 연결 확인

저장소 루트에서 `.ga4/token.json`과 `.ga4/config.json`이 있는지 확인한다.

- 없으면 **ga-auth 스킬**로 연결(로그인 → 속성 선택)부터 한다. 이 스킬이 대신 로그인하지 않는다.
- `.ga4/venv/bin/python`이 없으면 ga-auth의 의존성 설치 절차를 먼저 따른다.
- `.ga4/`는 OAuth 토큰이 들어 있어 gitignore 대상이다. 내용을 채팅·커밋·PR에 옮기지 않는다.

## 1단계 — 이벤트 목록 동기화 확인

`ga_dashboard.py`의 `FUNNEL`과 `collect()`의 파라미터 이름은 `src/constants/analytics.ts`의
`GA_EVENTS`·`GA_PARAMS`를 복사한 것이다. 이벤트·파라미터가 추가·변경됐으면 먼저 스크립트를 맞춘다.
GA 맞춤 정의(측정기준·측정항목)에 등록되지 않은 파라미터는 보고서에서 쪼개지지 않는다.

## 2단계 — 생성

저장소 루트에서 실행한다(기간 기본 28일, `--days`로 변경).

```bash
.ga4/venv/bin/python .claude/skills/ga-dashboard/ga_dashboard.py --days 28
```

기본은 **운영 호스트만** 집계한다(localhost·프리뷰 배포는 이벤트의 대부분이라 섞이면 지표가 오염된다).
개발·프리뷰까지 보려면 `--host all`을 붙인다. 도메인이 바뀌면 스크립트의 `PROD_HOST`와 `index.html`의 호스트 조건을 함께 바꾼다.

결과는 `.ga4/dashboard/ga_dashboard.html`(+ `.json`)이다. 경로만 알려주고 HTML을 열어 보게 한다.

## 3단계 — 해석 (숫자를 읽어 줄 때 지킬 것)

- **표본 경고를 먼저 본다.** 모드별 `game_mode_select` 200건 미만이면 방향성만 말하고 판단하지 않는다.
- **운영 사이트가 어느 버전인지 확인한다.** 운영(`release`)에 배포되지 않은 이벤트는 운영 데이터에 0으로 나온다(예: 방식 선택 화면 이벤트).
- **"미수집(등록 이전 데이터)" 행**은 맞춤 정의 등록(2026-10-16) 이전 데이터라 모드·완주율을 말할 수 없다.
- **인과를 말하지 않는다.** "게임이 강도를 N 낮춘다"가 아니라 두 방식 간 상대 비교와 악화 비율만 근거로 한다.
- **`buffer_skipped = true` 세션은 모드 비교에서 제외**한다(스크립트의 악화 비율은 이미 제외 값).
- **선택 비중은 한 방식을 없앨 근거가 아니다.** 제거 검토는 모드별 200건 + 4주 이상 + 완주율·악화·일관성 3조건을 모두 충족할 때만.
- 사용자 수는 브라우저 기준 근사치다. 이유(왜 나갔는지)는 데이터로 알 수 없으니 추정이라고 밝히고 인터뷰를 제안한다.
- **정체성 필터**: 데이터가 재방문·기록 열람·통계·공유 쪽을 가리켜도 스트릭, 아카이브, 개인 통계, SNS 공유는 제안하지 않는다.
- 텍스트·메모·텍스트 길이·사용자 식별자는 수집하지 않으므로 요청받아도 만들지 않는다.

## 4단계 — 보고

핵심 수치(완주율, 가장 큰 이탈 구간, 악화 비율), 표본·미수집 한계, 다음에 확인할 것을 짧게 정리한다.
측정하지 않았거나 확인하지 못한 값은 `미확인`으로 구분하고 만들어 내지 않는다.
