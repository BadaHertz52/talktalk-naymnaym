# Project Diary (톡톡냠냠 전용)

오늘 작업을 사실 기준으로 모아 프로젝트 일지 끝에 한 날짜 블록으로 추가한다.
일지는 나중에 히스토리와 이력서·포트폴리오, 위키 의사결정 아카이브의 후보 출처가 된다.

## 0단계 — 일지 경로 확인

저장소 루트 `.env.local`의 `PROJECT_DIARY_PATH` 값을 읽는다.

- 키가 없거나 파일이 없으면 만들지 말고 사용자에게 경로를 물어본다.
- 절대경로를 스킬·커밋·PR에 적지 않는다. `.env.local`은 gitignore 대상이다.

## 1단계 — 일지 형식 파악

일지의 마지막 날짜 블록 하나를 읽고 형식을 그대로 따른다. 전체를 읽지 않는다.

- 날짜 줄은 `- 10/13` 형식, 하위는 탭 들여쓰기 불릿.
- 맨 위 줄은 굵게 쓴 한 줄 결과(이슈·PR 번호, 커밋 해시, 테스트 상태).
- 마지막은 `다음에 할 것` 블록.

## 2단계 — 사실 수집

추측하지 않고 아래에서 확인한 것만 쓴다.

- `git log --since=<오늘 00:00> master`, 오늘 머지된 PR 본문(`gh pr view <N>`)
- 이번 세션에서 한 작업과 결정
- 필요하면 `.claude/plans/`·실행계획 문서의 해당 이슈 항목

## 3단계 — 작성 원칙

- **결정에는 이유를 한 줄 붙인다.** "무엇을 했다"보다 "왜 그렇게 했다"가 남아야 한다.
- 막힌 것, 실수, 되돌린 것도 쓴다. 성공만 나열하지 않는다.
- 실제로 돌려 보지 않은 것은 `미확인`으로 구분한다. 통과한 것으로 쓰지 않는다.
- 측정하지 않은 수치를 만들지 않는다.
- 날짜별 잡담이 아니라 나중에 읽고 판단 근거로 쓸 내용만 남긴다.
- 위키에 올릴 만한 판단이 있으면 한 줄로 표시해 둔다(릴리즈 때 `/wiki-decision-log`가 후보로 씀).

## 4단계 — 추가

1. 초안을 채팅에 보여준다.
2. 승인을 받으면 일지 끝에 추가한다. 같은 날짜 블록이 이미 있으면 새로 만들지 말고 그 블록에 이어 쓴다.
3. 추가한 줄 수와 날짜만 짧게 보고한다.
